================================================================================
1. VISAO GERAL DO SISTEMA
================================================================================

O CDB Simulator e uma aplicacao desktop para simulacao de rendimentos de
investimentos em renda fixa (CDB, juros compostos) e controle financeiro
pessoal. O projeto foi desenvolvido em Python com interface grafica usando
CustomTkinter, seguindo uma arquitetura em camadas (Clean Architecture) para
separar logica de negocio da interface.

Funcionalidades Principais:
- Simulacao de juros compostos com aportes mensais recorrentes
- Calculo de Imposto de Renda regressivo (tabela brasileira de renda fixa)
- Suporte a taxas prefixadas e pos-fixadas (% do CDI)
- Controle Financeiro pessoal (receitas, despesas, investimentos)
- Banco de dados SQLite criptografado em repouso
- Interface grafica responsiva com tema claro/escuro
- Animacoes dinamicas em botoes e cards
- Backup e restauracao de dados financeiros
- Empacotamento como executavel unico (.exe) via PyInstaller
- Camada de Casos de Uso (Use Cases) para orquestracao de regras de negocio

================================================================================
2. ARQUITETURA DO SISTEMA
================================================================================

O projeto adota uma Clean Architecture com separacao em camadas:

  Camada de Apresentacao (UI)
  main_gui.py -> src/ui/gui/
        ↓ (usa)
  Camada de Casos de Uso (Use Cases)  <-- NOVA CAMADA
  src/use_cases/
        ↓ (orquestra)
  Camada de Servicos
  src/services/
        ↓ (injeta / consome)
  Camada de Dominio
  src/domain/
        ↓ (persiste)
  Camada de Repositorios
  src/repositories/

Princípios SOLID Aplicados:
| Princípio | Aplicação no Projeto |
|-----------|---------------------|
| SRP | Cada modulo tem responsabilidade unica (models para dados, strategies para taxas, chart para graficos, etc.) |
| OCP | YieldStrategy e abstrata; novas estrategias de investimento podem ser criadas sem modificar codigo existente |
| LSP | CompoundInterestStrategy e CDIStrategy sao intercambiaveis |
| ISP | Contrato YieldStrategy e enxuto (get_monthly_rate(), get_description()) |
| DIP | Servicos e casos de uso dependem de abstracao (YieldStrategy, FinancialRepositoryProtocol), nao de classes concretas |

3. CAMADAS DO SISTEMA
================================================================================

3.1 Camada de Dominio (src/domain/)
Contem as regras de negocio puras, sem dependencias de UI ou infraestrutura.

models.py:
- calcular_aliquota_ir(dias): Retorna aliquota regressiva de IR baseada em dias corridos
  (<=180: 22.5%, 181-360: 20%, 361-720: 17.5%, >720: 15%)
- SimulationParams: Dataclass imutavel com parametros de entrada (valor inicial, aporte mensal, meses, meta)
- SimulationResult: DTO com resultado completo (investido, juros, saldo final, IR, liquido, timeline, campo truncado)
- MonthlyRecord: Registro mensal com investido, juros do mes e saldo total

strategies.py:
- YieldStrategy: Classe abstrata com contrato get_monthly_rate() e get_description()
- CompoundInterestStrategy: Taxa fixa prefixada (ao mes ou ano, nominal ou equivalente composta)
- CDIStrategy: CDB pos-fixado baseado em percentual do CDI com taxa base anual configuravel

financial_models.py:
- TransactionType: Enum (INCOME, EXPENSE, INVESTMENT)
- FinancialCategory: Categoria com validacao de nome (max 120 chars), cor hex (#RRGGBB), tipo e status ativo/inativo
- FinancialTransaction: Transacao com validacao de valor (>0 centavos), categoria, data e notas (max 1000 chars)
- FinancialSummary: Resumo com totais por tipo e calculo de taxa de investimento

constants.py:  <-- NOVO
- Constantes centralizadas de negocio e seguranca (single source of truth)
- MAX_SIMULATION_MONTHS, MAX_SIMULATION_BALANCE, ZERO_TOLERANCE
- LIMITE_MONETARIO, limites de taxa (TAXA_JUROS_MAX, CDI_PERCENTUAL_MAX, CDI_BASE_MAX)
- Faixas de IR por dias, nomes de arquivos de tema e banco

financial_utils.py:  <-- NOVO
- Utilitarios financeiros puros (sem dependencia de UI ou repositorio)
- parse_amount_to_cents, format_cents, parse_br_date
- period_range, summary_for, expense_by_category, allocation, monthly_expenses
- DEFAULT_CATEGORIES

3.2 Camada de Casos de Uso (src/use_cases/)  <-- NOVA CAMADA
Orquestram a execucao de regras de negocio entre a Interface (UI)
e as camadas de Servico / Dominio / Repositorio.

simulate_investment.py:
- SimulateInvestmentUseCase: Caso de uso para simulacao de investimento
- SimulationInput: DTO de entrada com dados brutos da UI
- SimulationOutput: DTO de saida pronto para exibicao na UI
- Orquestra: conversao de valores, validacao de limites, criacao de estrategia,
  chamada ao serviço e retorno de resultado

financial_use_cases.py:
- FinancialUseCases: Caso de uso para controle financeiro
- CRUD de categorias e transacoes
- Consultas agregadas (resumo, alocacao, despesas por categoria, mensais)

__init__.py: Exporta SimulateInvestmentUseCase e FinancialUseCases

3.3 Camada de Servicos (src/services/)

simulator_service.py:
- InvestmentSimulatorService.simulate(): Executa evolucao patrimonial mes a mes usando Decimal para precisao monetaria
- InvestmentSimulatorService.calculate_months_to_target(): Calcula tempo para atingir meta usando formula analitica O(1) com fallback iterativo
- MAX_SIMULATION_MONTHS = 1200: Limite de seguranca anti-DoS (100 anos)
- ZERO_TOLERANCE = 1e-12: Tolerancia para comparacao de taxa com zero

financial_service.py:
- FinancialService: Gerencia categorias, transacoes, resumos, filtros por periodo e agregacoes
- Delegacao para financial_utils para metodos estaticos de parsing e agregacao

3.4 Camada de Repositorios (src/repositories/)

financial_repository.py:
- FinancialRepository: Gerencia persistencia SQLite com criptografia opcional
- Implementa FinancialRepositoryProtocol (interface abstrata)
- Tabelas: categories, transactions, audit_log, schema_metadata
- Criptografia: Banco armazenado como .enc (criptografado), descriptografado para arquivo temporario durante execucao, recriptografado ao encerrar
- Auditoria: Registra INSERT, UPDATE e DELETE de transacoes com timestamps
- CategoryInUseError: Impede exclusao de categoria com lancamentos associados

interfaces.py:  <-- NOVO
- FinancialRepositoryProtocol: Protocolo (interface abstrata) para repositorios
- Permite injecao de dependencia, mock em testes e troca de banco sem alterar servicos

db_encryption.py:
- DatabaseEncryption: Gerencia criptografia Fernet (AES-128 CBC + HMAC-SHA256)
- Chave pode vir de variavel de ambiente CDB_DB_ENCRYPTION_KEY ou arquivo .db_key
- Prioridade: variavel de ambiente > arquivo existente > gerar nova

3.5 Camada de Apresentacao (src/ui/)

gui/app.py:
- ModernAppGUI: Janela principal responsiva (CustomTkinter)
- Breakpoint em 860px para layout mobile/desktop
- Persistencia de tema claro/escuro em ~/.cdb_simulator_theme.json
- Validacao de entradas com mensagens de erro amigaveis
- Tratamento generico de excecoes
- Usa casos de uso (SimulateInvestmentUseCase, FinancialUseCases) para logica de negocio
- Imports relativos (eliminado acoplamento a 'src.')

gui/components.py:
- MetricCard: Cards de metrica com animacao de hover (cor de fundo e borda)
- PillButton: Botoes pilula com animacoes de hover e clique
- formatar_moeda() / formatar_tempo(): Formatadores de moeda brasileira e tempo

gui/theme.py:
- PALETTES: Cores para temas Light e Dark
- THEME_MODES: ("Light", "Dark")
- Modulo independente para evitar ciclos de importacao

gui/chart.py:
- InvestmentChart: Graficos Matplotlib reutilizaveis (timeline e barras)
- Reutiliza Figure/Canvas para evitar vazamento de memoria
- dispose(): Limpa recursos ao encerrar

gui/financial/dashboard.py:
- FinancialDashboard: Tela completa do Controle Financeiro
- CategoryDialog: Gerenciamento de categorias com selecao de cor pre-definida
- FinancialCharts: Graficos de donut e barras para alocacao de despesas
- Backup e restauracao de banco criptografado

gui/financial/financial_charts.py:
- Graficos reutilizaveis do dashboard financeiro (donut e barras)

5. DECISOES TECNICAS
================================================================================

4.1 Por que Decimal para calculos monetarios?
O simulador usa decimal.Decimal internamente para evitar erros de ponto flutuante
(float). Isso garante precisao exata em centavos, essencial para aplicacoes financeiras.

4.2 Por que IR por dias e nao por meses?
A tabela regressiva de IR do CDB no Brasil e baseada em dias corridos (ate 180, 181-360, etc.).
O codigo foi corrigido para usar dias (meses * 30 a partir de meses) para ficar alinhado
com a documentacao de negocio.

4.3 Por que banco criptografado?
O banco financeiro contem dados sensiveis (receitas, despesas, investimentos).
A criptografia Fernet protege os dados em repouso no disco.

4.4 Por que arquitetura em camadas?
Permite testar logica de negocio independentemente da UI, facilita manutencao e
permite trocar a interface (ex: web, mobile) sem alterar regras de negocio.

4.5 Por que PyInstaller onefile?
Gera um unico .exe facil de distribuir, sem exigir Python instalado no computador
do usuario final.

4.6 Por que camada de Casos de Uso?
Separa a logica de negocio da interface grafica. A UI apenas coleta dados e chama
casos de uso, ficando responsavel apenas por apresentacao. Isso melhora a
testabilidade e permite reutilizar a mesma logica em outras interfaces (CLI, API, etc.).

4.7 Por que imports relativos?
Eliminou o acoplamento ao nome do pacote 'src.', tornando o codigo mais portavel
e facil de manter se o projeto for movido ou instalado como pacote.

4.8 Por que interface abstrata (Protocol) para repositorio?
Permite injecao de dependencia, mock em testes e futura troca de banco de dados
(ex: PostgreSQL) sem alterar a camada de servicos.

6. COMO CADA COMPONENTE FUNCIONA
================================================================================

5.1 Simulacao de Juros Compostos

Para cada mes:
  1. Adiciona aporte mensal ao saldo
  2. Calcula rendimento = saldo x taxa_mensal
  3. Adiciona rendimento ao saldo
  4. Registra no timeline

Taxa mensal:
  - Se anual: (1 + i_ano)^(1/12) - 1 (equivalente composta)
  - Se mensal: i_mes / 100

Imposto de Renda:
  - Baseado em dias (meses * 30, ou dias reais se start_date/end_date fornecidos)
  - Aplicado sobre juros brutos no final

Fluxo via Caso de Uso:
  UI coleta dados -> SimulationInput -> SimulateInvestmentUseCase.execute()
  -> validacao -> servico.simulate() -> SimulationOutput -> UI exibe

5.2 Calculo de Meta (O(1))

Usa formula analitica de annuidade com aportes antecipados:

n = ceil( ln((FV + k) / (PV + k)) / ln(1 + r) )

Onde k = (PMT * (1 + r)) / r

Tem fallback iterativo se a formula analitica falhar.

5.3 Criptografia do Banco

Execucao:
  1. Ler chave (variavel de ambiente ou .db_key)
  2. Descriptografar financial.sqlite3.enc -> arquivo temporario
  3. Operar normalmente no banco temporario
  4. Ao encerrar: recriptografar temporario -> .enc
  5. Deletar arquivo temporario

5.4 Animacoes da Interface

- Botoes: Transicao de cor via interpolacao RGB (10 passos, 15ms cada), efeito de clique com escurecimento
- Cards: Transicao de cor de fundo e borda no hover (8 passos, 15ms cada)
- Eventos: <Enter>, <Leave>, <ButtonPress-1>, <ButtonRelease-1>

8. BUILD E DISTRIBUICAO
================================================================================

7.1 Gerar o executavel

```bash
# Instalar dependencias
pip install -r requirements.txt

# Gerar .exe
project update        # Windows CMD
.\project.ps1 update  # PowerShell
./project.sh update   # Git Bash
```

O resultado fica em dist/CDB_Simulator.exe.

7.2 Criar instalador Windows (Inno Setup)

1. Baixar e instalar Inno Setup (https://jrsoftware.org/)
2. Abrir CDB_Simulator.iss no Inno Setup Compiler
3. Clicar em Build -> Compile
4. Resultado: installer/CDB_Simulator_Setup_1.0.0.exe

O instalador cria:
- Atalho na Area de Trabalho e Menu Iniciar
- Entrada no Painel de Controle (desinstalar)
- Nao remove dados do usuario na desinstalacao

7.3 Fluxo de Atualizacao

```
1. Alterar codigo-fonte
2. Rodar: project update (testes + build)
3. Compilar CDB_Simulator.iss no Inno Setup
4. Executar o novo instalador
   -> Dados em ~/.cdb_simulator/ sao preservados
```

   ↓

   ↓

13. CONSIDERACOES DE MANUTENCAO
================================================================================

Para adicionar nova estrategia de investimento:
1. Criar classe herdando YieldStrategy em src/domain/strategies.py
2. Implementar get_monthly_rate() e get_description()
3. Registrar na GUI se necessario

Para adicionar novo caso de uso:
1. Criar modulo em src/use_cases/
2. Implementar classe com DTOs de entrada e saida
3. Exportar em src/use_cases/__init__.py
4. Injetar na UI via construtor de ModernAppGUI

Para adicionar nova animacao:
1. Seguir padrao de _on_enter, _on_leave, _animate_*
2. Usar self.after() para frames
3. Usar self.after_cancel() para cancelar animacoes anteriores

Para alterar regras de IR:
1. Modificar calcular_aliquota_ir() em src/domain/models.py
2. Atualizar testes em tests/test_domain.py
3. Atualizacoes de documentacao se necessario

Para alterar constantes de negocio:
1. Editar src/domain/constants.py (single source of truth)
2. Nenhuma outra mudanca necessaria (constantes sao importadas)
